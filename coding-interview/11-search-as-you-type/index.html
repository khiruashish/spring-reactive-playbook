    11. Search-as-You-Type with switchMap¶

    L2 ★★☆ · sampleTimeout debounce, distinctUntilChanged, switchMap cancellation

    Problem¶

    Turn keystrokes into search requests. Debounce (wait 300 ms of quiet), ignore queries shorter than 2 characters, skip repeats, and when a new query starts, cancel the in-flight search so stale results never overwrite newer ones.

    Key idea¶

    sampleTimeout(q -> Mono.delay(quiet)) is Reactor's debounce: a value is emitted only if no newer value arrives within the window. distinctUntilChanged drops a repeated query. switchMap subscribes to the search for the newest query and cancels the previous one, which is the operator that fixes the classic out-of-order bug where results arrive late and overwrite newer ones.

    sequenceDiagram participant K as keystrokes participant D as debounce 300 ms participant S as switchMap(search 600 ms) K->>D: j (0), ja (100), jav (200) D->>S: "jav" at 500 → search starts K->>D: java (700) D->>S: "java" at 1000 → CANCEL "jav", start "java" S-->>S: results for "java" at 1600 K->>D: "java " (1800) → strip → same → skipped

    Solution¶

    P11SearchAsYouType.java
    package com.example.reactive.playbook.codinginterview;

import java.time.Duration;
import java.util.List;
import java.util.function.Function;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

/** Problem 11: search-as-you-type: debounce keystrokes, skip duplicates, and CANCEL stale searches when a new one starts. */
public class P11SearchAsYouType {

    public static Flux<List<String>> results(Flux<String> keystrokes, Function<String, Mono<List<String>>> search, Duration quiet) {
        return keystrokes
                .map(String::strip)
                .sampleTimeout(q -> Mono.delay(quiet))     // debounce: emit only after `quiet` with no new keystroke
                .filter(q -> q.length() >= 2)              // don't search for "j"
                .distinctUntilChanged()                    // "jav" -> "java" -> "jav" still searches, "jav" twice doesn't
                .switchMap(q -> search.apply(q));          // new query cancels the in-flight one: no out-of-order results
    }
}
    P11SearchAsYouTypeTest.java
    package com.example.reactive.playbook.codinginterview;

import static org.assertj.core.api.Assertions.assertThat;

import java.time.Duration;
import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;
import java.util.concurrent.atomic.AtomicInteger;
import org.junit.jupiter.api.Test;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;
import reactor.test.StepVerifier;

class P11SearchAsYouTypeTest {

    @Test
    void debounces_cancelsStaleSearch_andSkipsDuplicates() {
        List<String> started = new CopyOnWriteArrayList<>();
        AtomicInteger cancelled = new AtomicInteger();
        StepVerifier.withVirtualTime(() -> {
                    Flux<String> keys = Flux.concat(
                            Mono.just("j"),                                                  // t=0
                            Mono.delay(Duration.ofMillis(100)).thenReturn("ja"),             // t=100
                            Mono.delay(Duration.ofMillis(100)).thenReturn("jav"),            // t=200  -> searched at 500
                            Mono.delay(Duration.ofMillis(500)).thenReturn("java"),           // t=700  -> searched at 1000, cancels "jav"
                            Mono.delay(Duration.ofMillis(1100)).thenReturn("java "));        // t=1800 -> same query after strip: skipped
                    return P11SearchAsYouType.results(keys, q -> Mono.delay(Duration.ofMillis(600))
                            .thenReturn(List.of(q + " tutorial", q + " streams"))
                            .doOnSubscribe(s -> started.add(q))
                            .doOnCancel(cancelled::incrementAndGet), Duration.ofMillis(300));
                })
                .thenAwait(Duration.ofSeconds(5))
                .expectNext(List.of("java tutorial", "java streams"))
                .verifyComplete();
        assertThat(started).containsExactly("jav", "java");
        assertThat(cancelled.get()).isEqualTo(1);
    }

    @Test
    void shortQueries_neverHitTheBackend() {
        List<String> started = new CopyOnWriteArrayList<>();
        StepVerifier.withVirtualTime(() -> P11SearchAsYouType.results(Flux.just("x"), q -> { started.add(q); return Mono.just(List.of()); }, Duration.ofMillis(300)))
                .thenAwait(Duration.ofSeconds(1)).verifyComplete();
        assertThat(started).isEmpty();
    }
}

    Walkthrough¶

    Code Why
    .map(String::strip) Normalise before comparing, so "java " and "java" count as the same query.
    .sampleTimeout(q -> Mono.delay(quiet)) A value is emitted only if no newer keystroke arrives within quiet. Intermediate prefixes such as "j" and "ja" never reach the backend.
    .distinctUntilChanged() Compares with the previous emitted query only, so "jav", "java", "jav" still searches all three, but "java" twice in a row searches once.
    .switchMap(q -> search.apply(q)) The newest query wins. The test records that "jav" was started and then cancelled (doOnCancel), and only the "java" results are emitted.
    StepVerifier.withVirtualTime + Mono.delay keystrokes Exact timings (0, 100, 200, 700, 1800 ms) are replayed deterministically and instantly.

    Complexity¶

    Approach Time Space
    per keystroke O(1) O(1) (one in-flight search)

    Run it¶

    ./gradlew :playbook-examples:test --tests '*P11SearchAsYouTypeTest'

    P11SearchAsYouTypeTest: 2 tests, 0 failures
  ✔ debounces · cancels stale search · and skips duplicates
  ✔ short queries · never hit the backend

    Common mistakes¶

    • flatMap(search): concurrent searches whose late responses for old queries overwrite newer results.
    • concatMap(search): searches queue up behind each other and the UI lags further and further.
    • Debouncing on the server only. Each keystroke still costs a request; debounce in the client too.

    Follow-up questions¶

    Does cancellation actually stop the HTTP request?

    With WebClient, yes: cancelling the subscription closes or releases the connection. Make sure the backend also stops work on client disconnect (WebFlux propagates cancellation to the handler's subscription).

    switchMap vs exhaustMap-style behaviour?

    switchMap: the newest wins and older work is cancelled (search, autocomplete). The opposite, ignoring new triggers while one is in flight (for example a "submit" button), has no direct Reactor operator. Use onBackpressureDrop with concatMap(..., 1), or a guard flag.
